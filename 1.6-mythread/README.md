# Обёрктка над ядрёными потоками.

Реализован базовый функционал на create, join. Добавил отмену (обычную и асинхронную!).
Ошибки старался обрабатывать в соответствие с аналогичными функциями pthread. Единственное,
мой join не проверяет ситуацию, когда 2 потока джойнят друг друга.

## Принцип ралботы

При создании потока, мы создаём стек, guard page, структуру `tcb` (thread control block), в
которой храним всё нужное для каждого потока. (`start_func`, `retval`, `arg`, ...).
Структуры `tcb` образуют двусвязный список. Это нужно для проверки, что вызывающий наши функции поток
передаёт нам правильный thread_id. Связный список защищён мьютексом (реализован через CAS + `futex()`).
Это также позволяет потокам получать свою структуру, не имея свой хендлер (`mythread_self()`).

Стоит отметить, что при создании потока я блокирую все сигналы (так просто спокойнее).
А ещё это, как я понял, позволяет потоку не попадать в обработчик отмены ещё раз, если мы уже были отменены.

### Обработка ошибок

Так как я не реализую TLS (thread local storage), то я не могу полагаться на `errno`. Поэтому

1. Я использую свою обёртку над сисколлами для проверки возвращаемого значения системных вызовов
   (я могу дёргать какие-то функции из libc, где мне не важно, какое errno они выставят)
2. Все функции моей библиотеке возрващают -ERROR (как и делают в pthreads кстати).

### Как устроено присоединение?

Секрет во флаге `CLONE_CHILD_CLEARTID` при создании потока. Когда поток делает `exit()`,
то ядро выставляет `&tcb->tid` в 0 и делает `FUTEX_WAKE` на нём. Поток, делающий join,
ждёт на фьютексе на `&tcb->tid` пока тот не станет равным нулю. Любая остановка потока
в конечном итоге вызывает `mythread_exit()`, поэтому join должен отрабатывать нормально.

### Как устроена отмена

Обычная отмена просто выставляет `tcb->canceled = true`.
Поточная функция должна вызывать `mythread_testcancel()` постоянно
(типа как в java `while (!currentThread().interrupted()) {...}).

Асинхронная отмена через функцию `mythread_cancel_async()` посылает сигнал `SIGUSR1` потоку.
Я устанавливаю обработчик этого сигнала при первом создании потока.

# Стуктура

- `lib` - библиотека `mythread`.
- `test/t` - тесты. Есть как положительные, так и негативные

# Компиляция и запуск

Чтобы собрать либу, делаем:

```sh
make -C lib
```

И копируем хедер `lib/my_thread.h`.

## Как запустить тесты?

Заходим в папку `tests`, далее

```sh
export LD_LIBRARY_PATH=$PWD
make
./test
```

(Собирать либу не надо -- make сам это сделает)
